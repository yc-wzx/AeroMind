## 本轮实际修复

1. 目标交接运行器：GID 不变而导航端身份从未解析变为就绪时，原稳定计时可能一直为 None。现在启动稳定计时，保留身份/QoS/匹配数检查；真实 Full 接受确认通过。
2. 轨迹时间一致性：规划器部分轨迹生成/推进使用系统墙钟，而 executor/仿真使用 ROS 时钟。统一规划器轨迹/FSM/碰撞时间和 executor 到 ROS 时钟；CPU 性能计时仍独立。未改优化算法、代价、速度或安全参数。实际 C++ 二进制在私有 DDS 域产出的 start_time≈21.88 s，与输入仿真时钟一致。
3. 矩形间距性能：加入保守 AABB 下界筛选，候选仍用原精确多边形距离；不删采样、不放宽安全门槛。312 点同一生产回调从约 55–58 ms 降到约 8 ms；随机几何、原始 GT 与旧函数一致。保留空墙输入原来的拒绝行为，并新增慢回调只读诊断。
4. 安全停车后恢复的无进展计时：同一航点从守卫拒绝恢复到可执行状态时，重新开始原有 2 秒无进展观察。连续拒绝仍按原机制重试；连续安全轨迹更新不会无限重置观察。最终输出守卫、阈值、planner 参数和路线均未放宽。
5. 工具留档：增加本地 ELF 递归链接依赖及全部本地安装 .so 内容封存、元数据哈希、原始文件关闭后校验；修正关闭进度写入与哈希顺序。

上述 runtime 修改会影响轨迹推进、任务重试时机和回调耗时，不能说只改了只读工具；最终速度的安全拒绝/等待停车判据没有放宽。

运行代码修改：`src/uav_planning/scripts/ego_trajectory_executor.py`、`gazebo_navigation_interface.py`、`provincial_safety_geometry.py`；`src/uav_bringup/launch/provincial_2025_provisional.launch.py`；EGO `planner_manager.h/.cpp`、`ego_replan_fsm.cpp`、`bspline_optimizer.h/.cpp`、`grid_map.cpp`。完整增量 patch：`tools/results/provincial_stage15_completion_20261001/incremental_runtime_and_tools.patch`。
