# RMUC 2025 地图语义与高度建模

本项目现在把传感器可见网格、场地 3D 几何、底盘地面占用和规划安全距离分开。正式导航 PGM 是机器人地面通行图，不再把 MID-360 高度的截面直接当成地面障碍。

## 数据层

| 层 | 文件或来源 | 含义 |
| --- | --- | --- |
| 场地视觉几何 | `models/rmuc_2025/meshes/rmuc_2025.stl` | RMUC 场地三角面网格 |
| Gazebo 静态碰撞 | `models/rmuc_2025/meshes/rmuc_2025_obstacles_collision.stl` | 保留原 STL 的 3D 障碍表面；只去掉可行驶的水平支撑面 |
| 地面 raw occupancy | `maps/rmuc_2025.pgm` | 机器人碰撞高度带与场地障碍三角面相交后的 XY 占用，供 GridRoute 使用 |
| 雷达高度截面 | `maps/rmuc_2025_lidar_slice.pgm` | 场地视觉网格在雷达世界高度的诊断截面，不供 GridRoute 使用 |
| 上游 2D 图 | `maps/rmuc_2025_source.pgm` | 原始比赛资源，保留作对照；缺少 3D 高度语义，不直接并入正式地面图 |

可将这几层理解为：传感器看到什么、场地表面在哪里、底盘会不会撞上，以及规划器额外留多大距离。它们是不同问题，不能用一张占用图代替。

## 底盘高度与地面支撑面

机器人碰撞体从当前 SDF 读取：底盘盒尺寸为 `0.52 × 0.42 × 0.18 m`，世界姿态给出底盘碰撞高度 `z=0.06–0.24 m`。地面图生成器在上下各加 `0.02 m` 的垂直安全 margin，因此实际投影范围是 `z=0.04–0.26 m`。参数可以通过 `--robot-z-min`、`--robot-z-max` 和 `--vertical-margin` 显式指定。

场地 STL 的大面积水平支撑面位于世界 `z≈0.20 m`。它代表可行驶地面，不是墙；生成器识别并排除与该支撑面共面的 203 个三角面。Gazebo 碰撞 STL 采用同一过滤规则。其余三角面保留原始 3D 高度，没有从 PGM 挤出 0.8 m 高的假墙。

## 原先约 500 个雷达截面候选格

候选集是雷达高度视觉截面相对原始上游 PGM 新增的 2,442 格。旧的每 1 cm 高度采样把其中 500 格判成“只在雷达高度可见”。本次逐三角面裁剪并检查 STL 局部拓扑后，这 500 格分为：

- 174 格在底盘碰撞高度带内有斜面或边缘表面，归为 Type B；
- 再有 4 格被 `0.02 m` 垂直 margin 纳入 Type B；
- 285 格没有高度带碰撞面，且雷达截面来自闭合邻接面，归为 Type A；
- 37 格没有高度带碰撞面，但对应局部 STL 面触及边界边或非流形边，归为 Type C，实体体积语义仍不确定。

整个 STL 有 2,616 条边界边、482 条非流形边。Gazebo 碰撞网格直接使用同一 STL 的障碍三角面（去除可行驶支撑面），所以 PGM 描述的是当前仿真碰撞表面；Type C 不代表真实场地的实体体积已验证。这 37 格落在两个小区域：`x=18.10–18.35,y=3.75–4.00` 与 `x=17.75–18.30,y=2.75–3.45`。它们距已确认的底盘高度障碍最近分别约 `0.05 m` 和 `0.28 m`，均小于底盘外接半径约 `0.334 m`，因此在现有 `0.55 m` clearance 下不会成为可通行的机器人中心位置。Type C 需要后续用更可靠的局部实体模型确认。

坐标 `(6.625, 3.225)` 现在在正式地面图中是自由格，中心离最近地面障碍约 `0.60 m`。该网格可以从上方结构下通过；安全距离仍由现有规划层处理。

## 规划安全距离与本轮静态结果

GridRoute 的 `0.55 m` clearance、EGO 的 `0.22 m` inflation 均保持不变。它们属于机器人中心的规划安全区域和局部规划膨胀，不是 raw ground occupancy 的几何来源。

离线连通性 sweep 使用 `0.15–0.55 m`。路线 A `(3,3) → (8.8,1.5)` 和路线 B `(8.78,1.50) → (17,8)` 在整个区间均无 GridRoute 路径。精确栅格连通分析显示，路线 A 的起点和目标在 raw ground 图中已属于不同自由空间分量；地图在 `x≈3.95–4.20 m,y≈0.45–4.50 m` 有与底盘高度带相交的纵向墙面，起点和目标分处两侧。路线 B 的起点和目标在 raw ground 图及 `0.55 m` 安全图中也属于不同分量。已知的横向实体墙位于 `y≈2.50 m`、`x≈10.25–15.62 m`，场地网格显示其高度约 `z=0.20–0.403 m`，确实与底盘高度带相交；该墙与相邻场地结构封闭了通往远端的路径。两条旧路线在当前固定高度二维地面图中都没有合法静态通路，故作为本仿真回归基准已失效（invalidated），不计为导航算法失败；这不证明三维场地经坡道、隧道也不可达。没有通过降低 clearance 或删除墙格来伪造连通。

起点所在的 `0.55 m` 连通分量内已有离线长距离候选，详见 `docs/rmuc_stage15_topology_verification.md`。官方 STEP 已确认两处旧路线墙体，但同时发现当前 STL 缺少中央高地的低位边界，整图核验尚未通过。因此只保留候选数据，暂不建立正式 benchmark manifest，也不开始 Stage 1.5 运行回归。

## 复现

在仓库根目录运行：

```bash
python3 tools/generate_rmuc_navigation_map.py --vertical-margin 0.02
python3 tools/generate_rmuc_collision.py
```

地图审计结果写入 `tools/results/rmuc_2025_ground_map_audit.json`。碰撞 STL 的扫掠高度投影与正式地面 PGM 逐格一致；本次校验为 27,770 个占用格，差异 0 格。
